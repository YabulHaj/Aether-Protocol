# Aether Social Preview

## Purpose

The Aether social preview should immediately communicate:

**autonomous agents + authorization + security enforcement + evidence**

without using exaggerated marketing claims.

---

## Image Dimensions

Target:

```text
1280 × 640 pixels
```

Use a wide 2:1 composition suitable for GitHub/social sharing.

---

## Visual Direction

### Overall style

* futuristic
* dark
* technical
* high-end cybersecurity
* clean
* minimal
* cinematic
* visually distinctive
* no generic stock-art appearance
* no human faces
* no robots with faces
* no padlock cliché
* no excessive text

The visual language should feel like a security control system from a distant future rather than a conventional SaaS dashboard.

---

## Main Composition

### Left side

Large title:

```text
AETHER
```

Under it:

```text
AUTHORIZATION FOR AUTONOMOUS AGENTS
```

Small supporting line:

```text
IDENTITY → INTENT → AUTHORITY → ACTION → EVIDENCE
```

---

### Center

A glowing abstract authorization boundary.

The central object should visually represent:

```text
AGENT
   ↓
AETHER
   ↓
ACTION
```

Use layered geometric rings / energy field / security boundary imagery.

The central boundary should have a clear separation between:

```text
AUTHORIZED
```

and

```text
DENIED
```

Avoid literal cartoon shields.

---

### Right side

Show several abstract agent/action signals approaching the boundary.

Some should continue through.

Some should be visibly stopped at the boundary.

The visual should communicate:

```text
request
   ↓
evaluation
   ↓
decision
   ↓
enforcement
   ↓
evidence
```

without requiring the viewer to read paragraphs.

---

## Color Direction

Primary environment:

```text
near-black / deep space
```

Primary accents:

```text
electric cyan
cool blue
subtle violet
```

Use green only for successful authorization.

Use red sparingly for denied actions.

Do not turn the entire image into neon rainbow artwork.

---

## Typography

The title should be extremely readable even when the preview is displayed small.

Preferred hierarchy:

```text
AETHER

AUTHORIZATION
FOR AUTONOMOUS AGENTS

IDENTITY → INTENT → AUTHORITY → ACTION → EVIDENCE
```

---

## Security Concept

The image should visually suggest that:

**identity alone is not sufficient.**

The agent must pass through an authorization boundary before reaching the protected action.

The boundary should communicate:

```text
IDENTITY
+
CONTEXT
+
AUTHORITY
+
ACTION
=
DECISION
```

---

## Branding Rule

Do not put:

* personal names
* immigration references
* NIW references
* commercial pricing
* customer logos
* unsupported security statistics
* "100% secure"
* "unbreakable"
* "kills AI"
* "stops every attack"

The social preview must remain technically credible.

---

## Intended Impression

A technical researcher should look at the image and immediately understand:

> This project is about controlling what autonomous software is allowed to do.

The image should create curiosity without needing sensational claims.

---

## Future Version

The social preview should remain compatible with future Aether releases.

Do not put a temporary benchmark number such as:

```text
50/50
```

in the main visual.

Benchmark numbers belong in the README and research artifacts where methodology and limitations can accompany them.
