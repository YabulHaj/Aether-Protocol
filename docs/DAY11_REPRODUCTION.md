# Aether: Clean-Directory Reproduction Guide

## 1. Purpose
This package provides a standardized, single-command environment allowing an independent technical evaluator to clone the repository and reproduce verified Aether authorization behavior, tests, and benchmarks without relying on the creator's machine-specific state.

## 2. What this reproduction proves
* The Aether enforcement point blocks or allows payloads based on the defined policy matching invariants under local test conditions.
* The local telemetry tests verify SSE event generation and payload mapping.
* The Attack Lab benchmark corpus successfully executes locally across the provided baselines.
* The system builds and runs successfully from a fresh directory.

## 3. What it does NOT prove
* Network latency, production infrastructure resilience, or remote SPIFFE/OIDC identity provider behavior (all tests currently run via httptest loopback).
* Organization-wide enterprise scale.
* Absolute deterministic behavior under high-concurrency production load.

## 4. Prerequisites
* **OS:** Windows 10/11 (for the provided PowerShell harness), Linux, or macOS.
* **Go:** Version compatible with the repository's go.mod (e.g., Go 1.21+).
* **Git:** Required to resolve the repository context.

## 5. Fresh clone procedure
To ensure a clean environment, clone the repository to a new directory:
\\\	ext
git clone <repository-url> aether-repro
cd aether-repro
\\\

## 6. Exact reproduction command
From the root of the repository, execute:
\\\powershell
.\scripts\reproduce.ps1
\\\

## 7. Expected output
The script will output the system context (OS, Go version, Git commit), run the core security test suite (go test -count=1 ./...), and execute the benchmark. A successful run will print **REPRODUCTION RESULT: PASS**.

## 8. Generated artifacts
Artifacts are written to evidence/reproduction_<timestamp>/ inside the repository:
* **
eproduction_manifest.json**: System context, run configuration, and results.
* **core_tests.log**: Raw output of the unit and integration tests.
* **enchmark_run.log**: Raw output of the benchmark execution.

## 9. How to interpret failures
* **FAIL:** If tests fail, security invariants have been violated, or a local code change broke the build.
* **INFRASTRUCTURE ERROR:** Indicates missing prerequisites (Go, Git) or that the script was run outside the repository context.

## 10. Security boundary
The Aether server remains authoritative at all times. The reproduction script does not bypass authorization, mock security answers via the browser, or manipulate evidence stores.

## 11. Creator-controlled evidence limitation
Any artifacts generated by executing this script in the creator's environment remain creator-controlled validation.

## 12. How an independent evaluator can run it
An evaluator follows the Fresh Clone Procedure (Step 5), runs the reproduction command (Step 6), and inspects the resulting logs to verify they match published baseline claims. The package is intended to enable independent reproduction; this repository's creator has not classified successful local execution of this package as independent validation.

## 13. Current known limitations
* The script relies on httptest which limits true external socket testing.
* Full integration with a remote production identity provider requires infrastructure beyond this local loopback harness.
